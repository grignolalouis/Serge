\chapter{MCP Server Implementation}

\section{Architecture}

The MCP server is implemented as a \textbf{single Go binary} that loads seed data from JSON files at startup and exposes 21 read-only tools via the Model Context Protocol over stdio. The architecture follows a clean layered design:

\begin{itemize}[itemsep=0.3em]
    \item \textbf{Repositories:} In-memory data stores loaded from JSON seed files
    \item \textbf{Services:} Business logic (e.g., computing supplier on-time rates from PO history)
    \item \textbf{Controllers:} Interface between services and the MCP layer
    \item \textbf{MCP Server:} Tool registration and stdio transport via \texttt{trpc-mcp-go}
\end{itemize}

The server is built with Go~1.23 and depends on \texttt{trpc-mcp-go} v0.0.12 for the MCP protocol implementation.

\chapter{Use Case Validation}

The three use cases defined in Week~4 were tested with the live MCP server connected to Claude Code. All three were validated successfully.

\section{UC-1: Order Status Inquiry}

\textbf{Query:} ``What is the status of order ORD-005?''

The agent correctly:
\begin{enumerate}[itemsep=0.2em]
    \item Called \texttt{oms\_get\_order} to retrieve order details (customer, status, dates, line items)
    \item Called \texttt{tms\_track\_order} to find the associated shipment and tracking info
    \item Returned a unified response with order info + shipping status
\end{enumerate}

\textbf{Result:} The agent identified that ORD-005 was shipped on Feb~10, two days after being placed and four days before the required date. It correctly listed both line items with quantities and prices, and computed the total (\$14,750).

\textbf{Tool calls:} 2 (optimal)

\section{UC-2: Delayed Order Root Cause Analysis}

\textbf{Query:} ``Why is order ORD-007 delayed?''

The agent correctly performed the full cross-system investigation:
\begin{enumerate}[itemsep=0.2em]
    \item Called \texttt{oms\_get\_order}: order is processing, priority urgent, required by Feb~12
    \item Called \texttt{tms\_track\_order}: no shipment found (order stuck at fulfillment)
    \item Called \texttt{wms\_check\_inventory}: only 8 units available, 50 needed (shortfall of 42)
    \item Called \texttt{wms\_get\_product}: confirmed product is Nam Doc Mai Mango Box 5kg
\end{enumerate}

\textbf{Result:} The agent correctly identified the root cause: \textit{insufficient inventory} (8 units available vs.\ 50 required). It noted the order is 5+ weeks overdue and the inventory is below the reorder point of 20.

\textbf{Tool calls:} 4 (appropriate for the diagnostic chain)

\section{UC-3: Supplier Performance Comparison}

\textbf{Query:} ``Compare the performance of our suppliers''

The agent correctly:
\begin{enumerate}[itemsep=0.2em]
    \item Called \texttt{srm\_compare\_suppliers} to get side-by-side performance metrics
    \item Called \texttt{srm\_list\_suppliers} to get full supplier profiles
    \item Generated a structured comparison table with all key metrics
\end{enumerate}

\textbf{Result:} The agent produced a detailed comparison identifying Somchai Mango Farm as the top performer (100\% on-time, 2.7-day avg lead time) and Northern Fruits Co.\ as the weakest (0\% on-time, 8.5-day avg lead time). It included actionable insights about which supplier to use for urgent orders.

\textbf{Tool calls:} 2 (optimal)

\chapter{Documentation}

Two documentation files were created in the \texttt{serge/docs/} directory:

\section{MCP Setup Guide}

\textbf{File:} \texttt{docs/MCP\_SETUP.md}

This guide documents how to build and configure the MCP server from scratch. It covers:
\begin{itemize}[itemsep=0.2em]
    \item Prerequisites (Go 1.23+, Claude Code CLI)
    \item Build command (\texttt{go build})
    \item Configuration of \texttt{.mcp.json} and \texttt{.claude/settings.local.json}
    \item Verification steps
    \item Full reference of all 21 MCP tools
    \item Seed data summary
\end{itemize}

All machine-specific paths have been replaced with \texttt{<PROJECT\_ROOT>} placeholders so that any team member or future user can set up the system on their own machine.

\section{Supply Chain Modelisation}

\textbf{File:} \texttt{docs/SUPPLY\_CHAIN\_MODEL.md}

This document describes the V1 supply chain model and the roadmap toward a full B2B simulation:
\begin{itemize}[itemsep=0.2em]
    \item \textbf{V1 (current):} Static, read-only Thai mango distribution -- 5 SKUs, 3 suppliers, 1 warehouse, 50 customers, 2 carriers. Validates agent architecture and builds evaluation benchmarks.
    \item \textbf{V2:} Dynamic operations -- write operations, time simulation, multi-warehouse, more product categories.
    \item \textbf{V3:} Realistic B2B -- demand forecasting, contracts, payment terms, quality management, multi-carrier optimization.
    \item \textbf{V4:} Full simulation company -- international trade, real-time events, financial integration, compliance, multi-tenant.
\end{itemize}
